Împreună
John & Cristina

Buget comun, două taburi, aceeași împărțire egală. Aplicația este pregătită pentru GitHub Pages și Android.

Ce mai trebuie activat: GitHub găzduiește aplicația. Pentru ca Save să salveze pentru amândoi, creați un proiect Supabase și completați două valori publice în config.js. Folosiți apoi același cod privat pe ambele telefoane. Nu sunt necesare conturi separate în aplicație.

1. Ce fișiere folosești

  • DE-INCARCAT-PE-GITHUB: aplicația gata compilată. Încarci conținutul acestui folder în rădăcina repository-ului.
  • supabase/setup.sql: configurează salvarea comună și generează codul vostru privat.
  • supabase/reset-code.sql: folosești doar dacă pierzi codul sau vrei să îl schimbi.
  • Restul folderelor sunt sursele aplicației. Nu este nevoie să le încarci pentru varianta simplă.

2. Creează salvarea comună

  1. Intră pe Supabase și creează un proiect dedicat, de exemplu buget-john-cristina. Doar persoana care configurează proiectul are nevoie de cont Supabase. Planurile și limitele sunt prezentate pe site.
  2. Deschide SQL Editor → New query.
  3. Deschide pe calculator supabase/setup.sql cu Notepad, copiază tot conținutul în SQL Editor și apasă Run.
  4. În Results apare cod_privat, un șir lung de 64 de caractere. Copiază-l într-un manager de parole și trimite-l privat Cristinei. Acesta este codul comun de acces.
  5. La o nouă rulare, scriptul păstrează datele și codul existent. Dacă nu ai păstrat codul, rulează reset-code.sql și folosiți noul cod pe ambele telefoane.

Nu pune codul privat în GitHub, în config.js sau în linkul public. Oricine deține codul poate deschide și modifica bugetul. Codul este reținut pe telefon; nu trebuie reintrodus la fiecare vizită.

3. Completează config.js

În proiectul Supabase, găsește Project URL și Publishable key în panoul Connect sau în Settings → API / API Keys. Se poate folosi și cheia publică legacy anon.

Deschide DE-INCARCAT-PE-GITHUB/config.js și completează:

window.BUDGET_CONFIG = {
  url: 'https://PROIECTUL-TAU.supabase.co',
  key: 'CHEIA-PUBLICA-PUBLISHABLE-SAU-ANON'
};

Aceste două valori sunt publice. Nu folosi cheia secretă, service_role sau parola bazei de date. Copiază aceleași două valori și în public/config.js, pentru a le păstra dacă reconstruiești aplicația mai târziu.

4. Încarcă pe GitHub Pages

  1. Creează un repository, de exemplu buget-impreuna.
  2. În repository: Add file → Upload files.
  3. Încarcă toate fișierele și folderul assets din DE-INCARCAT-PE-GITHUB. Fișierul index.html trebuie să fie direct în rădăcina repository-ului, nu într-un subfolder. Nu încărca fișierul ZIP ca atare.
  4. Salvează prin Commit changes.
  5. Deschide Settings → Pages. La Source alege Deploy from a branch, apoi main și /(root). Apasă Save.
  6. După publicare, linkul va avea forma https://NUMELE-TAU.github.io/buget-impreuna/.

Nu ai nevoie de server Node, PHP, GitHub Actions sau comenzi pe calculator pentru această variantă. Dacă browserul nu include fișierul ascuns .nojekyll la upload, îl poți crea din GitHub: Add file → Create new file → .nojekyll.

5. Deschide același buget pe ambele telefoane

  1. Deschide linkul publicat în Chrome pe Android.
  2. Apasă Conectează telefoanele sau pictograma de setări.
  3. Introdu codul privat generat de SQL. Cristina introduce același cod pe telefonul ei.
  4. Verifică să apară Buget comun, nu Mod local.
  5. Modifică o poziție și apasă Salvează. Așteaptă mesajul Salvat pentru amândoi.
  6. Pe al doilea telefon, deschide aceeași lună. Datele se încarcă la deschidere și se actualizează la 15 secunde cât timp aplicația este în prim-plan. Poți apăsa și Actualizează.
  7. Din meniul Chrome, alege Adaugă pe ecranul de pornire / Instalează aplicația.

Modul local este pentru folosire pe un singur dispozitiv. Salvările locale nu sunt vizibile pe celălalt telefon și nu se importă automat în bugetul comun. Pentru sincronizare este necesar internetul. Dacă salvarea eșuează, modificările rămân pe ecran: reîncearcă înainte să închizi aplicația.

6. Cum folosiți bugetul

  • Alege luna din partea de sus. O lună nouă pornește de la sumele planificate în luna anterioară (implicit 5.000 lei pentru fiecare salariu), fără plăți confirmate și fără transferuri. Când salvezi un Planificat nou, de exemplu 6.000 lei, acesta apare și în lunile următoare.
  • În tabul fiecăruia apar veniturile și plățile din contul său. Toate cheltuielile sunt comune, inclusiv cei 800 lei pentru hrană, ratele și cele trei fonduri.
  • Hrana apare inițial la John doar pentru evidența plătitorului. Apasă pe rând și schimbă Din contul cui? dacă o plătește Cristina. Dacă plătiți amândoi, împarte suma în două rânduri, câte unul la fiecare.
  • Apasă pe orice rând pentru a modifica denumirea, planul, suma finală și data. Suma efectivă goală înseamnă neîncasat/neplătit; zero înseamnă confirmat cu valoarea zero.
  • Bifa confirmă încasarea/plata la valoarea planificată. Pentru o valoare diferită, editează rândul. Pentru plăți parțiale, separă partea achitată și restul pe rânduri diferite.
  • Bonusurile sunt venituri comune: sunt incluse în proiecție, dar intră în calculul efectiv doar după încasare. Poți adăuga oricâte alte venituri sunt necesare.
  • Rata 2 pornește de la zero. Când începe, setează 1.900 lei în luna respectivă și apoi în lunile în care se aplică.
  • După confirmarea salariilor și cheltuielilor, transferul recomandat folosește doar banii încasați. Până atunci, este afișată explicit o estimare pentru finalul lunii.
  • După ce trimiți banii prin bancă, apasă Înregistrează transfer, apoi Salvează. Aplicația va scădea transferul deja făcut din următoarea recomandare.
  • Transferurile dintre voi nu sunt cheltuieli comune și nu micșorează totalul banilor de împărțit.

Sumele se introduc și se salvează în lei întregi. Dacă totalul are un leu impar, acel leu îi revine Cristinei. Soldul afișat este soldul bugetului lunii, nu soldul bancar real și nu include economiile din lunile anterioare.

7. Exemplu de calcul, inclusiv hrana

ElementLei
Salariu John + salariu Cristina + bonus14.750
Chirie și facturi4.000
Hrană, cheltuială comună800
Rata 1 / Rata 21.900 / 0
Cele trei fonduri3.000
Rămâne în total5.050
Fiecare primește2.525

Dacă John achită chiria, hrana și rata 1, iar Cristina cele trei fonduri, Cristina îi transferă lui John 475 lei, când sunt încasate inclusiv bonusurile.

Dacă bonusul nu a intrat încă: Cristina → John 550 lei. După înregistrarea acelui transfer și încasarea bonusului: John → Cristina 75 lei. Astfel, ajungeți tot la 2.525 lei fiecare.

Când rata 2 este 1.900 lei și este plătită de John: rămân 1.575 lei fiecare, iar Cristina îi trimite lui John 1.425 lei, inclusiv bonusul de 150 lei.

8. Datele salariilor, copii și actualizări

Ziua 9 pentru John și ziua 15 pentru Cristina se mută înapoi peste weekend și sărbătorile legale din România, inclusiv Paștele ortodox. De exemplu, 9 august 2026 cade duminică: data estimată devine vineri, 7 august. Data poate fi modificată manual dacă angajatorul plătește altfel sau există zile libere suplimentare. Calendarul este orientativ și folosește regulile cunoscute la septembrie 2026.

Pictograma de descărcare exportă luna curentă ca JSON pentru arhivare. Fișierul conține date financiare; păstrează-l privat. Nu există import automat din JSON în această versiune.

Pentru a modifica ulterior codul aplicației: instalează Node.js compatibil cu package.json, rulează npm ci, apoi npm run dev. Verifică prin npm test, reconstruiește prin npm run build și încarcă noul conținut al folderului dist pe GitHub, cu config.js completat. Fișierele statice folosesc căi relative și funcționează indiferent de numele repository-ului.

După o actualizare, închide și redeschide aplicația sau reîncarcă pagina. Datele comune rămân în Supabase. Codul privat poate fi revocat prin reset-code.sql fără pierderea bugetelor.

Verificări și surse

Au fost verificate calculele pe scenariile de mai sus, calendarul, evidența transferurilor și accesul la baza de date într-un motor PostgreSQL local (PGlite). Conectarea la proiectul vostru Supabase și publicarea pe GitHub rămân de efectuat după completarea configurației. Nu a fost efectuat un test pe două telefoane reale.

Transfer intermediar până la salariul Cristinei

După încasarea salariului lui John, aplicația arată separat cât poate trimite Cristinei acum. Din soldul lui John se rezervă cheltuielile sale neconfirmate; restul se împarte egal cu Cristina, ținând cont de transferurile deja făcute. Cheltuielile atribuite Cristinei sunt plătite ulterior din salariul ei.

Exemplu: 8.600 − 4.000 − 800 − 1.900 = 1.900 lei disponibili. John trimite Cristinei 950 lei acum. După salariul Cristinei și cele trei fonduri, Cristina trimite înapoi 1.500 lei, dacă bonusul nu a intrat. După bonus, John mai trimite 75 lei. Dacă bonusul intră înaintea egalizării finale, Cristina trimite 1.425 lei.

Înregistrează fiecare transfer efectiv, apoi Salvează. Pentru schimbarea unei cheltuieli, apasă Modifică suma, editează suma planificată sau suma efectiv plătită, apasă Aplică modificările și apoi Salvează. Bifarea unei plăți la suma planificată nu eliberează bani în plus: suma era deja rezervată.
